Install

From a terminal (recommended)

macOS and Linux:

curl -fsSL https://lautaro005.github.io/opencue/install.sh | sh

Windows (PowerShell):

irm https://lautaro005.github.io/opencue/install.ps1 | iex

Then start it with opencue (or from Applications, the Start menu or your app menu). The scripts install the latest release for your user without admin rights:

SystemInstalls toCommand
macOS 11+ (Apple silicon and Intel)~/Applications/OpenCue.app~/.local/bin/opencue
Linux x86-64~/.local/opt/opencue/OpenCue.AppImage + app menu entry~/.local/bin/opencue
Windows 10/11%LOCALAPPDATA%\OpenCueadded to your PATH

If ~/.local/bin isn't on your PATH, the script prints the line to add. Uninstall on macOS/Linux with curl -fsSL https://lautaro005.github.io/opencue/install.sh | sh -s -- --uninstall (your data is kept); on Windows use Settings → Apps.

Or download one from GitHub Releases:

The apps aren't notarized or code-signed by Apple or Microsoft yet. On macOS, a downloaded .dmg is blocked the first time: open System Settings → Privacy & Security and choose Open Anyway (the terminal install doesn't need this). On Windows, SmartScreen may show More info → Run anyway. Updates are signed and checked by the app.

Your first agent

The first time you open OpenCue a floating walkthrough asks your name, connects a provider, picks a default model and creates your first agent. Replay it from Settings → General. To do it by hand:

  1. Open Settings → Providers (Ctrl+,) and set one up — paste an API key, or pick Ollama / LM Studio if you run models locally. Settings → Models then lists its models, with a search bar and switches to hide the ones you never use.
  2. Click + at the top of the sidebar → Create Agent. Give it a name, a face, a sentence about what it should help with, and the provider and model.
  3. Say hi. Click the person icon at the top right to open its profile, or the screen icon to open its computer.

Closing the window keeps OpenCue in the tray so automations and running agents keep working. Quit from the tray icon.

Model providers

Every agent uses one provider and model, picked when you create it or later in its profile → Model. Settings → Providers shows a container for every supported provider; click one to connect it. Settings → Models lists the models of the providers that are ready — search them and switch off the ones that shouldn't appear in pickers; the star sets a provider's default model.

ProviderHow it signs in
OpenAI, Anthropic, xAI (Grok), Google Gemini, Meta Muse, Mistral, Groq, OpenRouter, CheaperInference, Ollama CloudAPI key, stored on this computer (secrets.json, mode 0600)
Ollama, LM Studio, any OpenAI-compatible serverBase URL, no key needed for local servers
ChatGPT / Codex, Claude Code, Grok Build, Muse Code, Mistral Vibe, Antigravity“Backend CLI”: OpenCue runs the official codex, claude, grok, muse, vibe or agy program you are already logged in to (Grok, Muse, Vibe and Antigravity answer in text only). Models listed are the ones each CLI accepts. Vibe also reads MISTRAL_API_KEY and Antigravity signs in with your Google account in the browser the first time you run it.

Why the CLI route? OpenAI and Anthropic don't offer sign-in for third-party apps with consumer subscriptions, and copying their tokens breaks their terms. Running the official CLI keeps your subscription inside the official client.

OpenCue tools for CLI agents

CLI agents get OpenCue's own tools — memory, web, skills, their computer, files, email and catalog apps — through MCP: OpenCue hands the CLI a server started as opencue mcp-serve --agent <id>. Turn it off per agent in profile → Model → OpenCue tools. In Ask first mode actions that need approval (sending email, commands on your computer, deleting memories…) are put to you on the yellow card in the chat. Claude Code is started with only OpenCue's server, so your other MCP servers (configured in the CLI) aren't visible to the agent, and your own MCP servers configured in OpenCue aren't passed on.

Profile & avatar

Click an agent's face in its profile to change it in a floating window: ten faces, twelve shapes and a color row. The profile is organized like this:

  • Assets — Mails (its inbox), Computer (where it runs commands) and Files (everything shared in the chat).
  • Configurations — Model, Apps, Skills, Instructions, Memory, Voice and Permissions.
  • Automations — what wakes the agent up by itself.

Instructions & memory

Instructions are the agent's job description, added to every conversation. They are saved as agents/<id>/INSTRUCTIONS.md. The soul (agents/<id>/SOUL.md) says who the agent is: personality, tone and values. Every agent also gets a short built-in prompt that tells it it is an agent inside OpenCue; you never see or edit it.

A new agent opens the chat by asking what its job will be. It writes its own instructions and soul from what you tell it, and keeps them up to date as you talk (models without tools get the same result from a small pass after each reply). Edit either in the agent's profile, or turn Let the agent write its own profile off.

Memory is a list of facts the agent keeps about you and its work, in agents/<id>/MEMORY.md. Agents save facts with the remember tool, look them up with recall and delete with forget (which asks first). You can add, delete or edit the Markdown directly.

  • Shared memory (memory/GLOBAL.md) is visible to every agent that has “Use shared memory” on.
  • Learn from conversations automatically is on by default: after each reply the model decides whether anything is worth remembering, sends facts every agent should know to the shared memory, skips duplicates and merges the list when it passes 40 entries. Turn it off per agent in its Memory page.

About me (Settings → Account) is a description of yourself that every agent reads as background, together with your name. It stays on your computer and goes only to the model provider you chose.

Agents talking to each other

No group needed: in a 1:1 chat an agent can ask another one with send_to_agent (it knows the other agents' names) and gets the reply back. The chat shows a Chat with … pill that opens their conversation, with a Back to … button. Type @ in the composer to pick the agent you want it to ask. The agent that answers can't pass the work on again.

Group chats

Create one with + → Create group chat. The first member is the owner.

  • @Name makes that agent answer. Without a mention, the owner's model picks who should reply.
  • Agents hand work to each other by mentioning them or with send_to_agent.
  • Automatic turns (group details) caps how many hand-offs happen before the group waits for you.

Files

Attach files with + → Files in the message box, by dragging them onto the chat, or by pasting an image. Up to 10 files per message, 25 MB each.

  • Each file is copied into the workspace of the agent (or of every member of a group) as files/<name>, so agents with a computer can open it with their tools.
  • Pictures (PNG, JPEG, GIF, WebP) are sent to models that can see images; small text files (up to 40 KB) are included in the message.
  • Agents with a computer send files back with share_file — a report, a spreadsheet, a chart — and they appear in the chat like yours.
  • Click a file to open it; hover for Save as… and Show in folder. Every file shared in a chat is listed in the agent's Files page or the group's Files section.

Files are kept in the files/ folder of your data folder.

Artifacts

When you ask for something substantial — a page or small app, a diagram, a report, a spreadsheet, a deck, a script — the agent makes it with create_artifact instead of pasting it in the chat. The chat shows a card and a panel opens next to it, with a Preview and a Code view, a version picker, copy and Save as….

  • Every version is a file in the agent's profile → Files, where clicking it opens the same panel. The Word, Excel, PowerPoint and PDF previews are drawn from the text the agent sent, so they show the content, not Office's exact layout.

Dashboard

The home screen shows what is going on: the agents working right now, plans in progress, automations with their next run, recent chats and usage. Click the Dashboard entry at the top of the sidebar, or press Esc inside a chat, to come back to it (a half-written message keeps its first Esc for itself).

The page is plain HTML. To make it yours, go to Settings → General → Dashboard and pick the agent in charge; then run /dashboard in that agent's chat and say what you want (“big numbers on top, my automations as a list, dark colors”). The agent reads the current page with read_dashboard and rewrites it with update_dashboard; OpenCue sends the page live data as a window message. Reset goes back to the built-in page. The page runs in a sandbox with no network access.

/plan, /canvas and the chat's + menu

The + in the message box lists Skills in two groups: the system commands and, under their own label, your skills.

CommandWhat it does
/planThe agent plans (update_plan), then carries the plan out step by step without stopping to ask, with up to 80 tool steps. The reply is a card: what it is doing now, one segment per step, each action with its time, Approve / Deny when it needs you, Stop, and Open run for the whole list.
/dashboardRedesign the home screen (the agent chosen in Settings → General).
/create-skill, /create-automationThe agent writes a skill or an automation for itself.
/artifactThe agent makes a page, document, diagram or file as an artifact. While it writes, the chat shows a card with progress; when finished, click it to open the preview in the side panel.
/canvasOpens a canvas: a document or program you and the agent build together. Type in the side panel (Edit); every pause saves a version, and the agent reads your edits back before changing it.
/ai-councilIn a group: see AI council.

The computer, artifact and canvas panels resize by dragging their edge (double-click resets) and can be popped out with Open in its own window: a window you drag anywhere on the desktop and keep on top. The built-in browser follows it.

AI council

Create it from Templates → Groups → AI Council or Create group → Council, or turn on Every message goes to the council in any group's details. In a council every question runs in three rounds:

  1. Opinions — each member answers alone and at the same time, with their own model and personality.
  2. Review — each member reads all the answers without names (A, B, C…), ranks them and points out mistakes and gaps.
  3. Verdict — the chair (the group's owner) writes the answer: where the council agreed, where it split and who held each view, the next step and a confidence level.

/ai-council <question> does it once in any group; /ai-council --quick skips the review. An @mention skips the council and asks that member directly. A council makes about two model calls per member plus the verdict, so it costs more than a normal reply.

Coding groups

Create one from Templates → Coding team or Create group → Coding and pick the repository folder. The side panel has four tabs:

  • Sessions — the team grouped as Working, Pending (waiting for you), Blocked, Done and Idle, with each agent's last ACK / STATUS / BLOCKED / DONE line and branch. Add an agent offers Claude Code, Codex, Grok Build, Gemini (Antigravity), Mistral Vibe and Muse Code as command-line teammates, or any agent you have.
  • Changes — files changed against the last commit with a per-file diff, and Create pull request (the branch is pushed first).
  • PRs — open, merged and closed pull requests with checks, review state and conflicts; Fix CI sends the failing checks and the end of the log to the lead, Merge when ready turns on GitHub auto-merge and Merge now squashes. This uses the GitHub CLI (gh auth login) on your computer.
  • Repository — folder, branch, sync, GitHub account and the A worktree for each agent switch: teammates work in .opencue/worktrees/<name> on agent/<name>/work so parallel work never collides.

The team's system prompt (borrowed from Agent Relay) asks for short protocol lines — ACK when a task arrives, STATUS at milestones, BLOCKED instead of guessing, DONE with evidence — handoffs that say what "done" means, one writer per branch and never pushing to the default branch. A handoff stays open until the teammate answers DONE or BLOCKED; they are reminded once.

Terminals

The sidebar's + lists the command-line tools found on your computer: Claude Code, Codex, Grok Build, Gemini CLI, Antigravity, Mistral Vibe, Muse Code and a plain Terminal. Pick one, choose a project folder and it opens in a real terminal in the app (a darker background tells it apart from chats). Sessions stay in the sidebar under Terminals, remember their screen while the app is open and can be restarted or closed. They are your own installed, signed-in tools; nothing is sent anywhere by OpenCue.

Approvals

In Ask first mode (the default) these wait for you to click Allow in the chat:

  • Sending email
  • Commands and file writes on This computer or WSL
  • Deleting a memory
  • MCP and catalog-app tools not marked read-only

The request appears as a card with a moving yellow border and Accept / Reject. Agents can also ask you things with ask_user: a text field (and optional answer buttons) on the same kind of card. CLI agents get the same cards.

Fully autonomous runs everything without asking. Use it only with tools and content you trust.

Apps, MCP & Catalog

MCP servers

Settings → Apps accepts local servers (a command such as npx -y @modelcontextprotocol/server-filesystem ~/Documents), remote servers by URL (Streamable HTTP), or an imported Claude Desktop–style mcp.json:

{
  "mcpServers": {
    "filesystem": { "command": "npx", "args": ["-y", "@modelcontextprotocol/server-filesystem", "/home/me/Documents"] },
    "remote": { "url": "https://example.com/mcp", "headers": { "Authorization": "Bearer …" } }
  }
}

In an agent's Apps page choose all servers or only some.

Catalog

Settings → Apps → Catalog has cards for Composio (first), Gmail, Google Drive, Notion, Trello, GitHub, Supabase, Vercel and Outlook. The border shows the state: red not connected, yellow connect again (the sign-in expired or failed), green connected.

  1. Touch a card. Your browser opens the provider's sign-in page (OAuth); when you finish, OpenCue comes back to the front and the card turns green. Tokens are kept in oauth/<app>.json and refreshed automatically.
  2. Some providers (Gmail, Drive, Outlook, GitHub) don't let apps register themselves. Connect Composio first (the first card): touching those cards then signs you in through it, and the apps it connects show as small blue tags under the Catalog. Without Composio, create an OAuth app in the provider's developer console (redirect URL http://127.0.0.1) and enter its client ID (and secret) when asked.
  3. In an agent's profile → Apps, turn on the catalog apps it may use. Agents backed by the Claude Code or Codex CLIs get them through OpenCue's tools. Tools that change data ask first in Ask-first mode.

Skills

Skills are folders with a SKILL.md file, the same format as Claude Code Agent Skills:

---
name: weekly-report
description: Write the Friday status report from this week's notes and emails.
---

1. Read the notes in the workspace from Monday to today.
2. Search the inbox for "status" from this week.
3. Write a short report with Done / Next / Blocked.

Agents see each skill's name and description and load the full instructions with use_skill when a task matches. Create and edit skills in Settings → Skills, import one from a URL (GitHub links work), or let an agent save one with save_skill after you teach it something. Skills live in the skills/ folder and are shared by all agents; turn them off per agent in its Skills page.

Slash commands

Type / in the chat input to list commands; arrows and Enter pick one. Every installed skill is a command (/weekly-report for this month loads it and follows it). Three are built in: /create-automation makes the agent create an automation for itself (a schedule or new-email trigger; it asks first in Ask-first mode), /create-skill makes it write a reusable skill from what you described, and /dashboard (only for the agent in charge of the dashboard) has it redesign your home screen.

Copy, edit and regenerate

Hover an agent's reply for a copy button. On your last message, hover for Edit (resends the edited text) and Regenerate (the agents answer again); the answer after it is replaced.

Email

Profile → Mails → Add. Two account types:

  • IMAP / SMTP — any provider. Gmail, Outlook, Yahoo, iCloud and Fastmail servers fill in automatically. With 2-step verification use an app password. The password is stored on this computer (secrets.json).

The agent gets read_emails, search_inbox (plain words, or from: / subject:) and send_email. Sending waits for approval in Ask-first mode. Email content is treated as data: agents are told not to follow instructions written inside messages.

Automations

In the profile's Automations section click +. Each automation has a trigger and a prompt; when it fires, the prompt appears in the agent's chat as an event and the agent gets to work.

TriggerDetails
ScheduleFive-field cron in local time: minute hour day month weekday. 0 9 * * 1-5 = weekdays at 9:00. Runs missed while OpenCue was closed for more than 10 minutes are skipped.
New emailChecks the agent's inbox (IMAP) every 1–60 minutes. Optional filter on sender or subject. The first check only records what is already there, so old mail doesn't fire.
WebhookA private URL on your computer, e.g. http://127.0.0.1:7777/hooks/<token>. Anything you POST becomes trigger data.
Group messageWhen you write in a group the agent belongs to, optionally only if the message contains a keyword.
curl -X POST http://127.0.0.1:7777/hooks/YOUR_TOKEN \
  -H 'Content-Type: application/json' \
  -d '{"event":"deploy finished","status":"ok"}'

The automation list describes schedules in plain words (“Weekdays at 9:00”), and so does the editor as you type a cron expression. The webhook server listens on 127.0.0.1 only. Change the port in Settings → Computers → Webhooks. Automations run while OpenCue is open or in the tray.

Local VM: live desktop, resources and a folder that keeps its state

In an agent's profile → Computer → Local VM (Docker) you can turn on the live desktop (watch and use it in the Desktop tab), give the VM memory (1–16 GB) and CPUs, and choose the VM folder. That folder is the VM's home — desktop settings, browser profile, downloads and anything you install under it — so nothing is lost when you close OpenCue, the VM stops or it is recreated. By default it is a folder of its own inside OpenCue's data directory; pick any other folder to keep it where you want (an external disk, a synced folder…). Changing memory, CPUs, the desktop or the folder recreates the VM the next time it starts; the workspace and the VM folder are kept.

VMPal machines

VMPal virtual machines can be controlled by agents through MCP. Declare each machine in Settings → Computers → VMPal as TOML, the same way Codex declares MCP servers:

[mcp_servers.vmpal-work]
command = "/Applications/VMPal.app/Contents/Helpers/VMPalMachine.app/Contents/MacOS/VMPalMachine"
args = ["--mcp", "E7D-your-machine-id"]

In VMPal, turn on agent control for the machine (its Settings › AI Agents) and keep it running; if it is off, the agent starts it with its vmpal_start tool. Then open an agent's profile → Computer → VMPal and switch on the machines it may use — or press Add machine to paste a new table there, which adds it to the shared list and selects it. A machine starts the first time that agent replies; Test connection in Settings starts it now. VMPal machines are never part of “all MCP servers”, and in Ask-first mode their tools ask for approval unless they declare themselves read-only.

Setting up SPACE

Automatic (Linux x86_64 with KVM and Docker): in Settings → Computers → Perplexity SPACE, press Install SPACE. OpenCue checks the host (KVM, /dev/net/tun, Docker, tools, 30 GiB of disk, root or passwordless sudo), clones SPACE, runs its prerequisite and Firecracker installers and its bring-up, waits for the API, signs in as root@local with a password it makes up and keeps, and fills in the address (http://127.0.0.1:8080), the template (seed:latest) and the token, which it renews by itself. The first run takes a long while; Start and Stop bring the stack up and down. On macOS and Windows SPACE can't run: point OpenCue at a SPACE server on another Linux computer. The manual steps:

  1. On a Linux machine with /dev/kvm, run scripts/check-space-host.sh from the repository to check the basics.
  2. Install SPACE following its documentation.
  3. In Settings → Computers → SPACE, paste the API URL (for example http://host:8080/v1), the template to boot and the API token, then Test connection.

Each agent gets its own sandbox, created on first use and woken up when it was suspended.

Isolation, idle stop and setup (Docker)

Settings → Computers → Isolation chooses Per agent (each agent has its own container, folder and desktop) or Shared (one container, opencue-shared, and one desktop for every agent, kept in OpenCue's shared folder). Stop idle VMs after stops a VM nobody used for that many minutes (default 480, never while an agent is working, 0 never); files and installed apps stay in their folders and the VM starts again on its own. The Setup checklist walks through installing Docker, starting it, the one-time desktop download and creating the shared VM.

Desktop view (Docker and Podman)

Turn on Settings → Computers → Docker → Desktop view and Docker computers start from an image with a desktop you can watch and use in the Desktop tab of the Computer panel (widen it with the arrows icon). Programs the agent starts with run_command appear there (DISPLAY=:1).

With Podman the desktop is Cua's XFCE image (the one OpenMausBot uses), so there is no image to choose; it is on by default. In Settings → Computers the play button next to the start command runs it for you and Stop all VMs stops every OpenCue VM. The square Stop button in the Computer panel header stops a local VM (Docker or Podman) without losing its files or installed programs; the next command starts it again.

  • Default image: linuxserver.io Webtop (lscr.io/linuxserver/webtop:ubuntu-xfce, web port 3000). Any image that serves a web desktop works — noVNC, KasmVNC or Selkies — set its image and port.
  • The port is published on 127.0.0.1 only, on a random free port.
  • Existing computers keep their old container: use Restart computer in the Desktop tab. Restarting keeps the workspace.

Built-in browser

Turn on Browser in an agent's Computer page and the agent can use a browser pane: browser_open, browser_snapshot (the page text and a numbered list of what can be clicked or typed into), browser_click, browser_type and browser_close. The Computer panel opens by itself on its Browser tab (next to the VM; the terminal is always below) so you watch it work, and you can type an address or log in yourself.

  • A tab strip lets you open, switch and close pages; agents can open a page in a new tab.
  • The pane has its own cookies and storage, separate from your browsers; Clear browsing data wipes them.
  • In Ask first mode a new site asks first. Only public http/https pages open, and the agent never types passwords: it asks you to.
  • It uses your system's web engine (WebKit or WebView2), so a few sites may look slightly different from Chrome.

Messenger (WhatsApp)

  1. Settings → Messenger: choose the agent that answers and, optionally, the numbers it may answer.
  2. Press Link WhatsApp, then in WhatsApp go to Settings → Linked devices → Link a device and scan the code.
  3. From then on every direct chat is answered by the agent, in its own conversation with that contact. Groups and status are ignored.
  4. In the agent's chat each answered message shows up as a green WhatsApp card: click it to see the question and the reply.

Everything runs in the app, so nothing is hosted for you and the app has to be open (or in the tray) to answer. Treat contacts as outsiders: in Ask first mode, anything sensitive their message leads to asks you first.

Templates, search & limits

The sidebar's + menu has Templates: ready-made agents and teams (Dr. Eggbot, PR Reviewer, Research Bot, Dewey…). The same window imports a Grok Bot from x.ai: paste a marketplace link (x.ai/bot/marketplace/bots/…) to get its instructions, memories, skills and routines, or a shared link (x.ai/bot/…), which only exposes the name and description.

The magnifier next to + (or ⌘K / Ctrl K) searches every chat for a message and jumps to it. Settings → Usage also shows the 5-hour and weekly limits of the Codex and Claude Code CLIs you connected, with a bar and the reset time.

Voice & local models

  1. Either create an ElevenLabs API key and paste it in Settings → Voice, or download models that run on your computer (below).
  2. Press the microphone in the message box, speak, press it again. Your speech is transcribed and sent. The phone button makes a voice call.
  3. With Read replies aloud on, the agent's answer is spoken. Pick a default voice there, or a voice per agent in its Voice page.
  4. Settings → Voice → Engines chooses, for speech to text and for text to speech, ElevenLabs, local models, or automatic (local when there is no ElevenLabs key).

Local models

Settings → Models → Local downloads speech models that run on your computer, so nothing you say leaves it. Sizes, licenses and memory are shown before downloading; the first download also fetches the small sherpa-onnx runtime.

NVIDIA PersonaPlex (real-time calls)

PersonaPlex is a 7B full-duplex speech-to-speech model: it listens and talks at the same time, like a phone call. In Settings → Models → Local → NVIDIA PersonaPlex: accept the model license on Hugging Face, paste a token, press Install (a private Python environment, needs Python 3.10+ and the Opus library) and Start (the first start downloads about 17 GB). It needs an NVIDIA GPU, or Use CPU memory too, which is much slower. When it runs, the phone button in a chat offers PersonaPlex (real time). Turn on Allow calls from my phone to get a QR code for a phone on the same network (accept the browser's certificate warning: the certificate is made on your computer).

Internet

Agents with web access get web_search (DuckDuckGo and Wikipedia, no API keys) and web_fetch (any page, converted to Markdown). Results are cached in the local database. If you host SearXNG, add its URL in Settings → Internet and it is queried first.

Working folder

In an agent's profile, Working folder shows where it runs commands and keeps files: by default a folder of its own inside OpenCue's data directory. Choose folder… (or type a full path) points it at a project or any folder you want it to work on; the folder is created if it doesn't exist, and Use the default goes back. Files you share and files it creates live there, and a Docker computer mounts it at /workspace. In Ask-first mode, commands and file writes on your computer still wait for your approval.

Notifications

Settings → Notifications turns on system notifications for finished replies and for actions waiting for your approval. By default they appear only when OpenCue isn't in front; you can show just “New message” instead of the text, and send a test. Where chooses between system notifications and the notch: a small black window at the top of the screen (growing out of the camera housing on a Mac) where a permission or a question is answered, with a thin pill of the agents working. A message you write while an agent works is queued and read at its next step. On macOS and Windows allow OpenCue in the system's notification settings if nothing appears. The icon in the menu bar (or tray) opens a menu with Open, Settings, Check for Updates and Quit.

Updates

OpenCue checks GitHub Releases for a new version a few seconds after it starts. When there is one, a note appears at the bottom of the sidebar; Settings → About → Install and restart downloads it, verifies its signature and restarts. Turn off the automatic check there. In-app updates work for the macOS app, the Windows installers and the Linux AppImage; .deb and .rpm installs update through a new download.

Data & privacy

SystemData folder
macOS~/Library/Application Support/opencue
Linux~/.local/share/opencue
Windows%APPDATA%\opencue\data

Inside: opencue.db (agents, chats, settings, automations, web cache), agents/<id>/ (instructions, memory, workspace), files/ (files shared in chats), memory/GLOBAL.md and skills/. Set OPENCUE_HOME to use another folder. Secrets (API keys, email passwords, tokens) are kept in a 0600 secrets.json (the system keychain is not used); catalog app tokens are in oauth/. See the privacy policy for what leaves your computer.

Command line

opencue-cli (zipped with each release) uses the same data folder as the app:

opencue-cli providers add anthropic --key sk-ant-…
opencue-cli agents create "Nova" --instructions "Plan my trips"
opencue-cli chat Nova --message "Find a quiet hotel in Montevideo"
opencue-cli mcp import ~/.config/Claude/claude_desktop_config.json
opencue-cli search rust async traits
opencue-cli mcp-serve --agent <id>   # OpenCue's tools as an MCP server (stdio)
opencue-cli where

The desktop binary understands opencue mcp-serve --agent <id> and opencue --version too.

Build from source

Rust (stable), Node 22+, and on Linux libwebkit2gtk-4.1-dev libayatana-appindicator3-dev librsvg2-dev. On macOS, the Xcode command-line tools.

git clone https://github.com/Lautaro005/opencue
cd opencue/apps/desktop
npm install
npm run tauri dev     # the desktop app
npm run tauri build   # installers for your system

Release builds create signed update bundles, so tauri build needs TAURI_SIGNING_PRIVATE_KEY; for a local build without it, add -c '{"bundle":{"createUpdaterArtifacts":false}}'.

FAQ

Is it really free?

Yes. You pay only for the model API you choose, or nothing with local models. The license lets you use, change and share OpenCue but not sell it.

Does OpenCue have phone numbers or payments like Cue?

No, on purpose: no phone, wallet or payments.

Is it safe to let agents run commands?

Prefer Docker or SPACE: they are isolated from your files. On This computer, keep the agent in Ask-first mode and read each command before allowing it. Report security problems privately — see the security policy.

Something broke.

Open an issue on GitHub with your system, version (Settings → About) and steps to reproduce.
