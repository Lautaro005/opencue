Install

Download the latest installer from GitHub Releases:

SystemFileNotes
Linux.AppImageRuns anywhere: chmod +x OpenCue*.AppImage and open it.
Debian / Ubuntu.debsudo apt install ./OpenCue_*.deb
Fedora / openSUSE.rpmsudo dnf install ./OpenCue-*.rpm
Windows 10/11.msi or -setup.exeThe setup.exe installs for the current user without admin rights.

Installers are not code-signed yet, so Windows SmartScreen may warn you the first time. macOS isn't distributed but builds from source.

Your first agent

  1. Open Settings → Models (Ctrl+,) and add a provider — paste an API key, or pick Ollama / LM Studio if you run models locally.
  2. Click + at the top of the sidebar → Create Agent. Give it a name, a face and a sentence about what it should help with.
  3. Say hi. Click the person icon at the top right to open its profile, or the screen icon to open its computer.

Closing the window keeps OpenCue in the tray so automations and running agents keep working. Quit from the tray icon.

Model providers

Every agent uses one provider and model, picked in its profile → Model. The model list loads from the provider.

ProviderHow it signs in
OpenAI, Anthropic, xAI (Grok), OpenRouter, CheapestInference, Ollama CloudAPI key, stored in your system keychain
Ollama, LM Studio, any OpenAI-compatible serverBase URL, no key needed for local servers
ChatGPT / Codex, Claude Code“Backend CLI”: OpenCue runs the official codex or claude program you are already logged in to

Why the CLI route? OpenAI and Anthropic don't offer sign-in for third-party apps with consumer subscriptions, and copying their tokens breaks their terms. Running the official CLI keeps your subscription inside the official client. Trade-off: CLI agents reply with text only — OpenCue's tools (memory, web, email, computer, MCP) need an API-key provider.

Profile & avatar

Click an agent's face in its profile to change it: ten faces, twelve shapes and a color row. The profile is organized like this:

  • Assets — Mails (its inbox) and Computer (where it runs commands).
  • Configurations — Model, Apps, Skills, Instructions, Memory, Voice and Permissions.
  • Automations — what wakes the agent up by itself.

Instructions & memory

Instructions are the agent's job description, added to every conversation. They are saved as agents/<id>/INSTRUCTIONS.md.

Memory is a list of facts the agent keeps about you and its work, in agents/<id>/MEMORY.md. Agents save facts with the remember tool, look them up with recall and delete with forget (which asks first). You can add, delete or edit the Markdown directly.

  • Shared memory (memory/GLOBAL.md) is visible to every agent that has “Use shared memory” on.
  • Learn from conversations automatically asks the model after each reply whether anything is worth remembering.

Group chats

Create one with + → Create group chat. The first member is the owner.

  • @Name makes that agent answer. Without a mention, the owner's model picks who should reply.
  • Agents hand work to each other by mentioning them or with send_to_agent.
  • Automatic turns (group details) caps how many hand-offs happen before the group waits for you.

Approvals

In Ask first mode (the default) these wait for you to click Allow in the chat:

  • Sending email
  • Commands and file writes on This computer or WSL
  • Deleting a memory
  • MCP tools not marked read-only, and Composio actions that may change data

Fully autonomous runs everything without asking. Use it only with tools and content you trust.

Apps, MCP & Composio

MCP servers

Settings → Apps accepts local servers (a command such as npx -y @modelcontextprotocol/server-filesystem ~/Documents), remote servers by URL (Streamable HTTP), or an imported Claude Desktop–style mcp.json:

{
  "mcpServers": {
    "filesystem": { "command": "npx", "args": ["-y", "@modelcontextprotocol/server-filesystem", "/home/me/Documents"] },
    "remote": { "url": "https://example.com/mcp", "headers": { "Authorization": "Bearer …" } }
  }
}

In an agent's Apps page choose all servers or only some.

Composio

Composio connects 1000+ apps (Gmail, Slack, Notion, GitHub, Google Calendar…).

  1. Create a Composio account and connect the apps you want in its dashboard.
  2. Paste your Composio API key in Settings → Apps → Composio. The User ID is the Composio user whose connected accounts agents should use (default if empty).
  3. Turn on Composio apps in an agent's Apps page. It gets two tools: composio_search to find an action and composio_execute to run it.

Skills

Skills are folders with a SKILL.md file, the same format as Claude Code Agent Skills:

---
name: weekly-report
description: Write the Friday status report from this week's notes and emails.
---

1. Read the notes in the workspace from Monday to today.
2. Search the inbox for "status" from this week.
3. Write a short report with Done / Next / Blocked.

Agents see each skill's name and description and load the full instructions with use_skill when a task matches. Create and edit skills in Settings → Skills, import one from a URL (GitHub links work), or let an agent save one with save_skill after you teach it something. Skills live in the skills/ folder and are shared by all agents; turn them off per agent in its Skills page.

Email

Profile → Mails → Add. Two account types:

  • IMAP / SMTP — any provider. Gmail, Outlook, Yahoo, iCloud and Fastmail servers fill in automatically. With 2-step verification use an app password. The password goes to your system keychain.
  • Gmail via Composio — uses the Gmail account connected in Composio.

The agent gets read_emails, search_inbox (plain words, or from: / subject:) and send_email. Sending waits for approval in Ask-first mode. Email content is treated as data: agents are told not to follow instructions written inside messages.

Automations

In the profile's Automations section click +. Each automation has a trigger and a prompt; when it fires, the prompt appears in the agent's chat as an event and the agent gets to work.

TriggerDetails
ScheduleFive-field cron in local time: minute hour day month weekday. 0 9 * * 1-5 = weekdays at 9:00. Runs missed while OpenCue was closed for more than 10 minutes are skipped.
New emailChecks the agent's IMAP inbox every 1–60 minutes. Optional filter on sender or subject. The first check only records where the inbox is, so old mail doesn't fire.
WebhookA private URL on your computer, e.g. http://127.0.0.1:7777/hooks/<token>. Anything you POST becomes trigger data.
Group messageWhen you write in a group the agent belongs to, optionally only if the message contains a keyword.
curl -X POST http://127.0.0.1:7777/hooks/YOUR_TOKEN \
  -H 'Content-Type: application/json' \
  -d '{"event":"deploy finished","status":"ok"}'

The webhook server listens on 127.0.0.1 only. Change the port in Settings → Computers → Webhooks. Automations run while OpenCue is open or in the tray.

Setting up SPACE

  1. On a Linux machine with /dev/kvm, run scripts/check-space-host.sh from the repository to check the basics.
  2. Install SPACE following its documentation.
  3. In Settings → Computers → SPACE, paste the API URL (for example http://host:8080/v1), the template to boot and the API token, then Test connection.

Each agent gets its own sandbox, created on first use and woken up when it was suspended.

Voice

  1. Create an ElevenLabs API key and paste it in Settings → Voice.
  2. Press the microphone in the message box, speak, press it again. Your speech is transcribed (Scribe) and sent.
  3. With Read replies aloud on, the agent's answer is spoken. Pick a default voice there, or a voice per agent in its Voice page.

Internet

Agents with web access get web_search (DuckDuckGo and Wikipedia, no API keys) and web_fetch (any page, converted to Markdown). Results are cached in the local database. If you host SearXNG, add its URL in Settings → Internet and it is queried first.

Data & privacy

LinuxWindows
Data folder~/.local/share/opencue%APPDATA%\opencue\data

Inside: opencue.db (agents, chats, settings, automations, web cache), agents/<id>/ (instructions, memory, workspace), memory/GLOBAL.md and skills/. Set OPENCUE_HOME to use another folder. Secrets (API keys, email passwords, tokens) go to the system keychain, or a 0600 secrets.json if there is none. See the privacy policy for what leaves your computer.

Command line

opencue-cli (zipped with each release) uses the same data folder as the app:

opencue-cli providers add anthropic --key sk-ant-…
opencue-cli agents create "Nova" --instructions "Plan my trips"
opencue-cli chat Nova --message "Find a quiet hotel in Montevideo"
opencue-cli mcp import ~/.config/Claude/claude_desktop_config.json
opencue-cli search rust async traits
opencue-cli where

Build from source

Rust (stable), Node 22+, and on Linux libwebkit2gtk-4.1-dev libayatana-appindicator3-dev librsvg2-dev.

git clone https://github.com/Lautaro005/opencue
cd opencue/apps/desktop
npm install
npm run tauri dev     # the desktop app
npm run tauri build   # installers for your system

FAQ

Is it really free?

Yes. You pay only for the model API you choose, or nothing with local models. The license lets you use, change and share OpenCue but not sell it.

Does OpenCue have phone numbers or payments like Cue?

No, on purpose: no phone, wallet or payments.

Is it safe to let agents run commands?

Prefer Docker or SPACE: they are isolated from your files. On This computer, keep the agent in Ask-first mode and read each command before allowing it. Report security problems privately — see the security policy.

Something broke.

Open an issue on GitHub with your system, version (Settings → About) and steps to reproduce.
